# [D-08] An admin can clear the moderation queue from a screen instead of an API client

**Lane:** D — AI & Trust
**Task ID:** D-08
**Size:** ~1 day
**Depends on:** **D-07**.
**Blocks:** nothing — it's the end of the moderation spine.

---

## Problem

`/admin/moderation` renders a placeholder. Held content can only be reviewed through
`/api/docs`, which means in practice nobody reviews it — and every held post stays
invisible to everyone but its author.

## Proposed outcome

`ModerationPage` — the pending queue as a reviewable list, with approve as a one-click
action and reject behind a required explanation.

## Acceptance criteria

- [ ] **Admin-gated**: an authenticated non-admin is redirected to `/403`; an anonymous
      visitor to `/login`.
- [ ] Renders the pending queue **oldest first**. Each card shows: the content type, the
      author, the body (and the title for questions), a link to its `question_id` context,
      and the automated `moderation_note` that caused the hold.
- [ ] **Approve** acts immediately.
- [ ] **Reject** opens a modal requiring a note — mirroring the 1–1 000 rule client-side —
      before it can be submitted.
- [ ] Acted-on items leave the list, and the queue refills as items clear.
- [ ] Empty state: "nothing to review".
- [ ] Errors surface as a toast and the card returns to its previous state rather than
      lying about what happened.

## Out of scope

* Any backend change (D-07 owns the endpoints).
* Editing content as a moderator. You approve or reject; the author edits.
* Deleting content, banning users, or a moderation history view.
* A live-updating queue. A refresh after each action is the design.

## The tests that grade this task

## Technical notes

**Constraints (requirements, not suggestions):**
* The client-side gate is **convenience, not security**. The server already returns 403
  (D-07 + `require_admin`); the redirect just avoids showing a broken page. Never rely on
  hiding a route.
* Mirror the note rule client-side, but still render the server's 400 if it comes back —
  same principle as every other form in this project.
* `useAuth()` gives you `user.role`. Wait for `isLoading` before deciding to redirect, or
  an admin gets bounced on first paint.
* `components/Modal.tsx` already handles focus-trapping and Escape. Use it.

**Files you will probably touch:**
* `frontend/src/pages/ModerationPage.tsx` — replace the `<Placeholder>`.
* `frontend/src/components/Modal.tsx`, `contexts/ToastContext.tsx` — read only.

**Suggested approach:**
1. The gate first: `useAuth()`, wait for `isLoading`, then redirect on anonymous or
   non-admin. Test it before building anything else.
2. Then the read-only queue.
3. Then Approve — call, then refetch the queue.
4. Then the Reject modal with its note field and validation.
5. Empty and error states last.

**Words you'll meet in this ticket:**
* **Route guard** — a component that decides whether to render a page or redirect.
* **Client-side gate** — a UI convenience that mirrors a server-side rule. The server rule
  is the real one.
* **Modal** — a dialog that takes focus until dismissed. Used here so a rejection can't be
  submitted without a reason.

## Verify it yourself

1. Visit `/admin/moderation` **logged out** → redirected to `/login`.
2. As a **normal user** → redirected to `/403`.
3. As an **admin** → the queue renders, oldest first.
4. Hold a question, an answer and a comment → all three appear, each with its
   `moderation_note` and a working link to its question context.
5. Click **Approve** on one → it disappears from the list, and the content is publicly
   visible in the app.
6. Click **Reject** → the modal opens; try to submit with an empty note → blocked. Enter
   a note → the item leaves the list, and its author can see the note on their post.
7. Clear the queue entirely → the "nothing to review" state.
8. Stop the backend and click Approve → a toast, and the card doesn't vanish as though it
   had worked.
9. Hard-refresh the page as an admin → no flash of the `/403` page before it loads.
