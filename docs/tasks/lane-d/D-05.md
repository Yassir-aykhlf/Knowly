# [D-05] A user can chat with the assistant and turn a good reply into their answer

**Lane:** D — AI & Trust
**Task ID:** D-05
**Size:** ~2 days
**Depends on:** **D-03**, **D-04**. Renders assistant Markdown with `<MarkdownBody>`
(**B-14**).
**Blocks:** integration milestone 8 — B-13's answer composer consumes the prefill you emit.

---

## Problem

`/ai` and `/ai/:conversationId` render placeholders. The streaming endpoint can only be
exercised with `curl`, so the app's headline feature is invisible — and there's no way for
a user to take something the assistant wrote and post it as an answer.

## Proposed outcome

Two screens: a list of conversations, and a chat view that streams the reply into a
growing bubble, can be stopped, handles the hourly cap gracefully, and offers "Use this as
my answer" on assistant messages.

## Acceptance criteria

### `AiPage` (`/ai`)

- [ ] Lists the caller's conversations: title, the linked question if there is one, and a
      relative time.
- [ ] A "New conversation" action, and a delete per row.
- [ ] Empty state.

### `AiConversationPage` (`/ai/:conversationId`)

- [ ] Streams via **`fetch` + `ReadableStream`** — not `EventSource`, which can't do a
      POST with a JSON body.
- [ ] Parses SSE blocks split on `\n\n`, appends `delta` tokens to a live-growing
      assistant bubble, and renders assistant Markdown with B's `<MarkdownBody>`.
- [ ] A **Stop generating** button aborts the fetch (the backend then cancels upstream and
      keeps the partial reply). After the stream ends, **reload the conversation** so the
      UI matches the server's canonical — possibly partial — turn.
- [ ] On **429**: read `Retry-After`, show a visible cool-down countdown that disables
      send until it elapses, and **put the user's unsent text back in the input**.
- [ ] On an `event: error`: show the sanitized message, and return the user's message so
      they can retry.
- [ ] Auto-scroll to the newest content.
- [ ] When the conversation is linked to a question, assistant messages carry a **"Use
      this as my answer"** action that navigates to `/questions/:id` with router state
      `{ prefillBody: <assistant text>, fromConversationId: <id>, isAiAssisted: true }`.

## Technical notes

**Constraints (requirements, not suggestions):**
* Use raw `fetch` + `ReadableStream` here — this is **the one place** in the app exempt
  from "always use `lib/api.ts`", because the wrapper parses a whole JSON body and this
  response never ends until it does. Everything else on these pages still goes through the
  wrapper.
* SSE blocks are separated by `\n\n`, and a chunk from the network can split **mid-block**.
  Keep a buffer, split on `\n\n`, and hold the remainder for the next chunk. Assuming one
  chunk equals one event is the classic bug here and it shows up as dropped tokens.
* Reload the conversation after the stream ends. The server's stored turn is the truth —
  especially after a stop, where the UI has more text than was persisted, or less.
* `AbortController` is how you stop a `fetch`.

**Files you will probably touch:**
* `frontend/src/pages/AiPage.tsx`, `frontend/src/pages/AiConversationPage.tsx` — replace
  the `<Placeholder>`s.
* `frontend/src/components/MarkdownBody.tsx` — read only (B-14's).

**Suggested approach:**
1. `AiPage` first — it's a list, a create button and a delete. Ordinary work, and it gets
   you a conversation to open.
2. Then the conversation view, read-only: load history and render it.
3. Then the send + stream loop. Get tokens appearing before you handle any error case.
4. Then Stop (`AbortController`) plus the post-stream reload.
5. Then the 429 countdown and the `event: error` path — both need the user's text
   returned to the input, so build that once and reuse it.
6. "Use this as my answer" last: `navigate('/questions/' + qid, { state: {...} })`.

**Words you'll meet in this ticket:**
* **`ReadableStream`** — the browser API for reading a response body as it arrives.
* **`AbortController`** — an object you can call `.abort()` on to cancel a `fetch`.
* **Chunk vs event** — the network gives you arbitrary byte chunks; SSE events are
  delimited by `\n\n`. They do not line up.
* **Router state** — data passed through a navigation without appearing in the URL.
* **Cool-down** — a visible timer during which an action is disabled.

## Verify it yourself

1. `/ai` → create a conversation, see it listed, delete another one.
2. Open a conversation, send a message → the reply **grows word by word** in the browser.
3. Send a long prompt and hit **Stop** halfway → generation stops; **reload the page** →
   the partial reply is there, and matches what the server stored.
4. Set `LLM_RATE_LIMIT_PER_HOUR=1`, send twice → the second attempt shows a countdown, the
   send button is disabled until it ends, **and your typed message is back in the input**.
5. Blank the API key, send → a readable error message, your text returned, no key
   material on screen.
6. Ask for a fenced code block → it renders as formatted code, not raw backticks.
7. Open a conversation **linked to a question** → assistant messages show "Use this as my
   answer". Click it → you land on the question page with the composer prefilled (once
   B-13 is in), and the posted answer comes back `is_ai_assisted: true`.
8. Send several messages → the view auto-scrolls to the newest content.
