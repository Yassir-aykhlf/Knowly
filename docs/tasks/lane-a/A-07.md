# [A-07] A profile lists the questions and answers that user has contributed

**Lane:** A — Identity & Access
**Task ID:** A-07
**Size:** ~1 day
**Depends on:** **A-06** (same visibility rules, same 404 behaviour).
**Blocks:** A-12 (the profile page's two tabs).

---

## Problem

A profile shows that someone has written 14 answers and gives you no way to read any of
them. The counts are a dead end.

## Proposed outcome

`GET /api/users/{id}/questions` and `GET /api/users/{id}/answers`, paginated and
visibility-filtered — with the awkward case handled properly: an answer whose parent
question the viewer isn't allowed to see must not leak that question's title.

## Acceptance criteria

### Both endpoints

- [ ] Unknown user id → **404**.
- [ ] Paginated with `page` / `limit`, returning `{ items, total, page, limit }`.
- [ ] Newest first.
- [ ] Visibility-filtered by the same rule as A-06 (strangers see approved only; the
      owner and admins also see their own pending/rejected).
- [ ] Anonymous viewers are allowed.

### `/questions` items

- [ ] Home-feed cards: `{ id, title, excerpt, tags, author, vote_total, answer_count,
      view_count, has_accepted_answer, created_at }`.
- [ ] `excerpt` is the body with whitespace collapsed, truncated to 240 characters
      (`schemas/common.py` already exports `excerpt()` — use it).
- [ ] `answer_count` counts **approved** answers only.

### `/answers` items

- [ ] `{ id, question_id, question_title, excerpt, vote_total, is_accepted, created_at }`.
- [ ] **The edge case:** an approved answer can hang off a question the viewer may not
      see. Visibility-filter the **parent questions** too, and when the parent is hidden
      or gone, render `question_title: "(removed question)"` and `is_accepted: false`.
      The hidden question's real title must never appear.

## Out of scope

* The profile card itself — A-06.
* The profile **page** and its tabs — A-12.
* Listing a user's comments or votes. Not in this project.
* Sort options. Newest first, always.

## The tests that grade this task

```bash
docker-compose exec backend pytest tests/lane_a/test_a07_profile_listings.py -v
```

Three tests.

| Test | What it pins down | AC |
|---|---|---|
| `test_questions_listing_paginates_and_shapes_cards` | 3 questions with `?page=1&limit=2` → `total == 3`, 2 items, and each card contains **all ten** card keys | pagination + shape |
| `test_unknown_user_listing_is_404` | a random UUID → **404** | not found |
| `test_answers_listing_masks_hidden_parent_question` | an **approved** answer on a **pending** question, viewed by a stranger → exactly 1 item, with `question_title == "(removed question)"` and `is_accepted is False` | the leak case |

That third test is the whole point of this ticket. Note what it does *not* do: it
doesn't hide the answer. The answer is approved, so it's listed — only its parent's
title is masked. Getting this backwards (hiding the answer entirely, or showing the
title) both fail.

**Not graded here, but still required:** newest-first ordering, the 240-char excerpt,
`answer_count` counting approved answers only, and the owner/admin half of visibility
(milestone `m2` territory).

## Technical notes

**Constraints (requirements, not suggestions):**
* `"(removed question)"` — that exact string, including the parentheses.
* Use `excerpt()` from `schemas/common.py`; four other places truncate the same way.
* Batch-load: one query for the page of rows, one for their parent questions, one for
  vote totals. Not one query per item.

**Files you will probably touch:**
* `backend/app/routers/users.py`, `backend/app/schemas/user.py`,
  `backend/app/schemas/question.py`.

**Suggested approach:**
1. `/questions` first — it's the same card Lane B builds for the feed, so coordinate
   with them rather than inventing a second shape.
2. `/answers`: fetch the page of answers, collect their `question_id`s, fetch those
   questions **with the visibility filter applied**, and build a `{id: question}` dict.
   Any answer whose parent isn't in that dict gets the masked title. That single lookup
   handles both "hidden" and "deleted" without a special case.

**Words you'll meet in this ticket:**
* **Information leak** — revealing something through a side channel. Here: the title of
  a held question, surfaced through its answer.
* **Batch-load** — one query for many rows instead of one query per row.
* **Excerpt** — a short preview of a longer body, cut to a fixed length.

## Verify it yourself

```bash
docker-compose exec backend pytest tests/lane_a/test_a07_profile_listings.py -v
```

By hand:
1. Create a user with 3 questions → `GET /api/users/{id}/questions?page=1&limit=2`
   returns 2 items and `total: 3`; page 2 returns the third.
2. Add an approved answer on a **pending** question, then fetch
   `/api/users/{id}/answers` **as a stranger** → the answer is listed,
   `question_title` is `"(removed question)"`, `is_accepted` is `false`, and the real
   title appears **nowhere** in the response.
3. Delete a question that has an answer → the answer's row still renders with the
   masked title rather than 500-ing.
4. Compare one item from `/api/users/{id}/questions` against one from
   `/api/questions` (B-03) — same keys, same types.
