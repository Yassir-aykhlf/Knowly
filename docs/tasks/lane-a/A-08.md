# [A-08] A user can change their display name and bio

**Lane:** A — Identity & Access
**Task ID:** A-08
**Size:** ~0.5 day
**Depends on:** **A-05**.
**Blocks:** A-12 (the Settings page's Profile section).

---

## Problem

A username is fixed at registration and a bio can never be written. Every profile in
the app is blank, and a typo in your name at sign-up is permanent.

## Proposed outcome

`PUT /api/users/me` — a partial update that changes only the fields you send, and
refuses a username someone else already holds even if they took it a millisecond ago.

## Acceptance criteria

- [ ] Body `{ username?, bio? }`. **Only the fields actually provided change** — sending
      just `bio` must not blank the username.
- [ ] `username`, if provided: re-validated (3–30 of `[A-Za-z0-9_-]`). If it differs
      from the current one and another user holds it → **409 `conflict`** with
      `fields: { username: ... }`.
- [ ] A **race** that slips past your pre-check must still surface the same 409: catch
      the database's unique-violation and translate it, rather than returning a 500.
- [ ] `bio`, if provided: trimmed, ≤ 500 characters → **400** otherwise. An empty (or
      whitespace-only) string stores **`null`**, not `""`.
- [ ] Returns the updated `UserMeOut`.

## Out of scope

* Password change (A-05), avatar (A-09), deletion (A-11) — same `/users/me` prefix,
  different tasks.
* The Settings page — A-12.
* Changing your email. Not in this project.
* A username-change cooldown or history. Not in this project.

Five tests.

| Test | What it pins down | AC |
|---|---|---|
| `test_update_username_and_bio` | both fields at once → **200**, and `bio` comes back **trimmed** (`"  hi there  "` → `"hi there"`) | update + trim |
| `test_empty_bio_becomes_null` | `{"bio": "   "}` → `bio is None` in the response. Whitespace is not a bio | empty → null |
| `test_bio_too_long_is_400` | 501 characters → **400** with `"bio"` in `fields` | length |
| `test_taken_username_is_409` | claiming another user's username → **409** with a truthy `fields["username"]` | uniqueness |
| `test_partial_update_leaves_other_fields` | set a bio, then send **only** a username → the bio survives | partial update |

That last test is the one that catches the most common bug in this endpoint: building
the update from a Pydantic model where unset fields default to `None`, and writing the
`None`s. Use `exclude_unset` (or check for the key's presence) to tell "not sent" apart
from "sent as null".

**Not graded here, but still required:** the username **format** rules (the test only
covers the taken-name case), and the race translation — a test can't easily produce a
real race, but a reviewer will read for the `try/except IntegrityError`.

## Technical notes

**Constraints (requirements, not suggestions):**
* "Not sent" and "sent as null" are different things. Pydantic's
  `model_dump(exclude_unset=True)` is the standard way to tell them apart.
* Empty bio stores `null`. A `""` and a `null` render differently downstream and one of
  them is wrong.
* Renaming yourself to the name you already have is **not** a conflict — check
  "differs from current" before you check "taken".

**Files you will probably touch:**
* `backend/app/routers/users.py`, `backend/app/schemas/user.py`.

**Suggested approach:**
1. `exclude_unset=True` to get only the provided fields.
2. Validate and normalise each provided field (trim the bio, empty → `None`).
3. Username: skip if unchanged; otherwise pre-check with a `SELECT`, then wrap the
   commit in `try/except IntegrityError` → rollback → raise the same 409. The
   pre-check is for a good message; the catch is for correctness.
4. Return `UserMeOut`.

**Words you'll meet in this ticket:**
* **Partial update** — a `PUT`/`PATCH` where absent fields mean "leave alone".
* **Race condition** — two requests interleaving. Here: both check "is `bob` free?",
  both see yes, both write. The database's unique index is what actually stops it.
* **IntegrityError** — the exception raised when the database refuses a write that
  breaks a constraint.

## Verify it yourself

```bash
docker-compose exec backend pytest tests/lane_a/test_a08_profile_edit.py -v
```

By hand:
1. Set a bio, then send only `{"username": "..."}` → the bio is still there.
2. Send `{"bio": "   "}` → the response has `bio: null`, and `psql` shows `NULL`, not
   an empty string.
3. Send a 501-character bio → 400 with `fields.bio`.
4. Try to take another user's username → 409 with `fields.username`.
5. Send your **own current** username → 200, not 409.
6. Send `{"username": "no spaces allowed"}` → 400, not a database error.
