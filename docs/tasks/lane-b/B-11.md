# [B-11] A logged-in user lands on a browsable feed of questions

**Lane:** B — Q&A Core
**Task ID:** B-11
**Size:** ~1 day
**Depends on:** **B-03**. Uses `<Avatar>` (A-09, stub renders initials until then).
**Blocks:** nothing — but it's the first screen anyone sees, so it's what the app *looks
like* to the rest of the team.

---

## Problem

`/home` renders a placeholder box. A user who logs in successfully arrives at nothing,
and the feed endpoint that B-03 built has no consumer.

## Proposed outcome

`HomePage` — the paginated feed with three sort tabs, cards that link into questions, and
an obvious way to ask one.

## Acceptance criteria

- [ ] Renders the paginated feed from `GET /api/questions`.
- [ ] Three sort tabs — **Newest / Votes / Unanswered** — reflected in the query string,
      so a sorted view is shareable and survives a reload.
- [ ] Changing tab or page refetches.
- [ ] Each card shows: title, excerpt, tags, author (avatar + name), vote total, answer
      count, view count, an "accepted" marker when `has_accepted_answer`, and a relative
      timestamp.
- [ ] Cards link to `/questions/:id`.
- [ ] A prominent "Ask a question" action links to `/ask`.
- [ ] Empty state when there are no questions — a first-run user must not see a blank
      screen and assume it's broken.
- [ ] Loading and error states exist; a failed fetch says so and offers a retry.

## Out of scope

* Any backend change. If a card needs a field the feed doesn't return, that's a B-03
  conversation.
* Search and filters — that's D-12's page, a separate screen.
* The question detail page (B-13) or the ask form (B-12).
* Infinite scroll. Plain pagination.

## The tests that grade this task

**There is no `test_b11_*.py`** — React pages have no pytest surface in this project.
`tests/lane_b/test_b03_question_feed.py` defines every field and every sort this page
renders, and must stay green.

## Technical notes

**Constraints (requirements, not suggestions):**
* Use the `api` wrapper in `lib/api.ts`, never bare `fetch`.
* `Question`, `QuestionListItem` and `Paginated<T>` already exist in `lib/types.ts` —
  frozen. Use them.
* `lib/format.ts` exports `relativeTime(iso)`. Use it.
* Put sort and page in the URL (`useSearchParams`), not in component state alone. It's
  the difference between a shareable view and one that resets on every back-button press.

**Files you will probably touch:**
* `frontend/src/pages/HomePage.tsx` — replace the `<Placeholder>`.
* A shared `QuestionCard` component — **Lane A's profile page (A-12) renders the same
  card shape**. Agree on one component with them rather than shipping two.

**Suggested approach:**
1. Fetch page 1 with the default sort, render a plain list. No tabs yet.
2. Extract the card into its own component once it looks right.
3. Add the tabs and pager, both driven off `useSearchParams`.
4. Empty, loading and error states last — but don't skip them; "it looked broken but was
   just empty" is the most common bug report on a screen like this.

**Words you'll meet in this ticket:**
* **Query string as state** — storing view state in the URL so it can be shared,
  bookmarked, and navigated back to.
* **Empty state** — what the screen says when there's legitimately no data. Not an error,
  not a spinner.

## Verify it yourself

1. Log in → `/home` shows questions, newest first.
2. Click **Votes** → the order changes **and the URL changes**. Reload → the same view.
   Press back → the previous sort.
3. Page forward and back → content changes, sort is preserved.
4. Click a card → the question detail page.
5. Click "Ask a question" → `/ask`.
6. Empty the `questions` table → the empty state, not a blank page or an endless spinner.
7. Stop the backend and reload → an error state with a retry, not a white screen.
8. Post a question with a 3 000-character body → the card's excerpt is one truncated
   line, not a wall of text.
