# [B-06] A user can answer a question

**Lane:** B — Q&A Core
**Task ID:** B-06
**Size:** ~1 day
**Depends on:** **B-04**. Calls moderation (**D-02**) and notifications (**C-01**) — both
stubbed.
**Blocks:** B-07, B-08, B-13 — and Lane D's "use this as my answer" hand-off.

---

## Problem

Questions can be asked and read, and nobody can reply. The site is a wall of unanswered
questions — and the `answers` table, the accept feature, answer voting and half the
notification vocabulary all sit idle behind this one endpoint.

## Proposed outcome

`POST /api/questions/{id}/answers` — screened like any other content, notifying the asker
when it goes live, and correctly refusing to credit someone else's AI conversation.

## Acceptance criteria

- [ ] Auth required. The parent question must exist **and be viewable** → **404**
      otherwise.
- [ ] Body `{ body, is_ai_assisted?, from_conversation_id?, attachment_ids? }`; `body`
      30–30 000 → **400** with `fields.body`.
- [ ] **Self-answering is allowed** — a question's author may answer their own question.
      That's a legitimate "I figured it out, here's how" post, not an abuse.
- [ ] **The AI-assisted flag:** if `from_conversation_id` is given, it must belong to the
      caller. If it doesn't exist or belongs to someone else, **silently force
      `is_ai_assisted = false`** — never attribute another user's conversation, and never
      error about it either.
- [ ] On approval, stage the question author's `answer_created` notification plus any
      `@mentions` (both idempotent — C-01 guarantees at-most-once). A **held** answer
      stages nothing for the question author; they'll be notified if and when it's
      approved.
- [ ] Bind attachments. Return **201** `AnswerOut`.

## Out of scope

* Editing and deleting answers — B-07. Accepting one — B-08.
* The answer composer UI — B-13.
* Building the AI conversation the flag refers to — that's D-03/D-05. You only check
  ownership of the id you're handed.
* Threaded replies to answers. Comments (B-09) are the only sub-level.

## Technical notes

**Constraints (requirements, not suggestions):**
* A foreign conversation id is **not** an error. Downgrade the flag and return 201.
  Erroring would leak whether that conversation exists.
* 404 (not 403) for a question the caller can't see — same reasoning as B-04.
* Answers are screened exactly like questions. There's no short-content bypass.

**Files you will probably touch:**
* `backend/app/routers/answers.py` (or `questions.py` for the nested route),
  `backend/app/schemas/answer.py`.

**Suggested approach:**
1. Load the question with `can_view`, 404.
2. Validate the body.
3. Resolve the AI flag: `is_ai_assisted = bool(is_ai_assisted and from_conversation_id
   and conversation_belongs_to_caller)`. One expression, no branching, no errors.
4. Insert → `screen_and_stage` → `bind_attachments` → commit → serialise.

**Words you'll meet in this ticket:**
* **Cross-attribution** — accidentally crediting one user's work to another. The reason
  the conversation-ownership check exists.
* **Fail silently (deliberately)** — here, quietly ignoring a bad flag instead of
  rejecting the whole request. Chosen because the answer itself is fine; only the badge
  is unearned.
* **Idempotent notification** — one that fires at most once for the same event, so
  "approved at creation" and "held then approved" both notify exactly once.

## Verify it yourself

```bash
docker-compose exec backend pytest tests/lane_b/test_b06_create_answer.py -v
```

By hand:
1. Answer someone's question → 201, and it appears in the question detail (B-04).
2. Answer **your own** question → 201.
3. Answer a `pending` question as a stranger → 404.
4. Post a 20-character answer → 400 with `fields.body`.
5. Once Lane D's conversations exist: post with your own `from_conversation_id` and
   `is_ai_assisted: true` → the badge sticks. Repeat with **another user's** conversation
   id → still 201, but `is_ai_assisted` comes back `false`.
6. Once C-01 has shipped: answering someone's question puts an `answer_created`
   notification in their inbox; answering **your own** puts nothing in yours.
