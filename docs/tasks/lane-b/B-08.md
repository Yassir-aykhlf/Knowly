# [B-08] An asker can mark the answer that solved their problem

**Lane:** B — Q&A Core
**Task ID:** B-08
**Size:** ~0.5 day
**Depends on:** **B-06**.
**Blocks:** B-13's accept control.

---

## Problem

`questions.accepted_answer_id` exists, B-04 sorts by it, and the feed reports
`has_accepted_answer` — and nothing can ever set it. Every question in the app is
permanently unsolved.

## Proposed outcome

`POST /api/questions/{id}/accept-answer` — the asker marks one answer as *the* answer,
can move the mark, and can take it back. Only an answer other people can actually read is
eligible.

## Acceptance criteria

- [ ] **Question-author only**, via `load_owned` (404 missing, 403 not-yours).
- [ ] Body `{ answer_id }`, or `{ answer_id: null }` to clear.
- [ ] When `answer_id` is set, the answer must:
  - [ ] belong to **this** question → **400 `invalid_answer`** otherwise;
  - [ ] be **approved** → **400 `invalid_answer`** otherwise, with the message "Only an
        approved answer can be accepted". Marking a question solved by an answer nobody
        else can see would be a lie to every future reader.
- [ ] Sets (or clears) `accepted_answer_id`, commits, and returns `{ accepted_answer_id }`.
- [ ] Accepting is a **toggle/move**: re-accepting a different answer just moves the
      pointer; there's no "unaccept first" step.

## Out of scope

* Notifications on acceptance. There is **no `answer_accepted` event** in the
  vocabulary — don't add one.
* Reputation, badges, or points. Not in this project.
* Letting a moderator accept on someone's behalf.
* The accept button — B-13.

## The tests that grade this task

```bash
docker-compose exec backend pytest tests/lane_b/test_b08_accept_answer.py -v
```

Four tests.

| Test | What it pins down | AC |
|---|---|---|
| `test_accept_approved_answer` | **200** with `accepted_answer_id` set to the answer; then posting `{"answer_id": None}` → `accepted_answer_id is None` | accept + clear |
| `test_only_owner_can_accept` | a non-author → **403** | ownership |
| `test_cannot_accept_held_answer` | a `pending` answer → **400** with `error.code == "invalid_answer"` | approved-only |
| `test_cannot_accept_answer_from_another_question` | an answer belonging to a different question → **400** | belongs-to check |

Note that the last two share **one error code**. `invalid_answer` covers both "not
yours" and "not approved" — different messages, same code. Don't invent a second one.

**Not graded here, but still required:** the move case (accept A, then accept B without
clearing → the pointer lands on B), and the exact message string for the approved-only
case.

## Technical notes

**Constraints (requirements, not suggestions):**
* Check `answer.question_id == question.id` explicitly. Without it, anyone could point
  their question at any answer in the database.
* The approved-only rule interacts with moderation: if an accepted answer later gets
  rejected by an admin, the pointer stays. That's out of scope here — mention it in your
  PR if it bothers you, but don't build it.

**Files you will probably touch:**
* `backend/app/routers/questions.py`, `backend/app/schemas/answer.py`.

**Suggested approach:**
1. `load_owned(db, Question, id, user, "question")` does the 404/403 for you.
2. `answer_id is None` → clear, commit, return.
3. Otherwise load the answer, run the two checks, set the pointer, commit, return.

**Words you'll meet in this ticket:**
* **Toggle / idempotent-ish action** — accepting the same answer twice is harmless;
  accepting a different one moves the mark rather than erroring.
* **Referential check in application code** — verifying "this answer belongs to this
  question" yourself, because no single foreign key expresses it.

## Verify it yourself

```bash
docker-compose exec backend pytest tests/lane_b/test_b08_accept_answer.py -v
```

By hand:
1. As the asker, accept an approved answer → 200; the feed's `has_accepted_answer` for
   that question flips to `true` and B-04 floats it to the top.
2. Accept a **different** answer without clearing → the pointer moves; only one is
   accepted.
3. Post `{"answer_id": null}` → cleared; the feed flag goes back to `false`.
4. As someone else, try to accept → 403.
5. Set an answer to `pending` in `psql` and try to accept it → 400 `invalid_answer`.
6. Take an answer id from a **different** question and try to accept it → 400.
