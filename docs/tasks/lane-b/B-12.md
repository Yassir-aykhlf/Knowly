# [B-12] A user can write and edit a question from a real form

**Lane:** B — Q&A Core
**Task ID:** B-12
**Size:** ~1–1.5 days
**Depends on:** **B-02**, **B-05**. Mounts `<FileUpload>` (**D-10**, stub renders nothing).
**Blocks:** nothing directly, but nobody can create content in the UI until it lands.

---

## Problem

`/ask` renders a placeholder. The only way to post a question is through `/api/docs`, and
the only way to fix a held one is a `PUT` by hand — which means the moderation loop
(post → held → edit → republished) can't be demonstrated at all.

## Proposed outcome

One page that serves both jobs: writing a new question and editing an existing one, with
validation that matches the server's, and a slot for file attachments.

## Acceptance criteria

- [ ] Fields: **title**, **body** (Markdown — a hint or a small preview is welcome), and
      **tags** as a chip input capped at 5.
- [ ] Client-side validation **mirrors the backend rules** (title 10–200, body
      30–30 000, ≤5 tags of 2–30 characters) for instant feedback.
- [ ] Server `fields` errors still render on submit — client checks are convenience, not
      a substitute.
- [ ] Mount `<FileUpload onUploaded>` (D-10), collect the returned attachment ids, and
      submit them with the question. **Until D-10 ships the stub renders nothing and
      `attachment_ids` is `[]` — the form must still work.**
- [ ] **Edit mode** preloads the existing question and calls `PUT`; on success it
      navigates to the question detail.
- [ ] When the author is editing **held or rejected** content, show the moderation banner
      (the same one B-13 defines) so they understand why they're re-submitting.

## Out of scope

* Any backend change (B-02 / B-05 own those).
* Building the file upload component — D-10. You mount it.
* A full Markdown WYSIWYG editor. A textarea plus an optional preview is the scope.
* Draft autosave. Not in this project.

## Technical notes

**Constraints (requirements, not suggestions):**
* Mirror the backend limits exactly. A client that allows 201 characters and a server
  that rejects them produces an error the user can't understand.
* Never trust client validation alone — always render the server's `fields` errors too.
  The 409-style cases can only come from the server.
* Use the `api` wrapper; read `fields` off the thrown `ApiError`.
* `lib/validation.ts` already exists — check what's in it before writing rules.

**Files you will probably touch:**
* `frontend/src/pages/AskPage.tsx` — replace the `<Placeholder>`.
* `frontend/src/components/FileUpload.tsx` — **read only**, it's D-10's.
* `frontend/src/lib/validation.ts`.

**Suggested approach:**
1. Create mode first: three fields, submit, navigate to the new question.
2. Then the tag chip input — it's the fiddliest control here. Enter or comma adds a chip,
   backspace on an empty input removes the last, cap at 5.
3. Then edit mode, driven by a route param or a prop. Same component, preloaded state,
   different verb.
4. Mount `<FileUpload>` early even though it renders nothing, so you find the layout
   problem now rather than the day D-10 lands.
5. The moderation banner last — it only appears in edit mode on non-approved content.

**Words you'll meet in this ticket:**
* **Chip input** — a text field that turns entries into removable tags.
* **Controlled component** — a React input whose value lives in state. Everything here is
  one.
* **Dual-mode form** — one component serving create and edit. Cheaper than two forms that
  drift apart.

## Verify it yourself

1. `/ask` → write a valid question → 201 and you land on its detail page.
2. Type a 9-character title → the error appears **before** you submit.
3. Force a server-side rejection (paste a 30 001-character body past the client check) →
   the server's `fields` error renders under the right input.
4. Add 5 tags → the input refuses a sixth. Remove one with backspace → it comes back.
5. Edit an existing question → the form is preloaded; save → you land on the detail page
   with the new content.
6. Set a question to `pending` in `psql`, open it in edit mode as its author → the
   moderation banner shows.
7. Confirm `attachment_ids: []` goes out on the wire while `<FileUpload>` is still the
   stub — and that the submit works anyway.
