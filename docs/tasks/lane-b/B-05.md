# [B-05] An author can fix or withdraw their own question

**Lane:** B — Q&A Core
**Task ID:** B-05
**Size:** ~1 day
**Depends on:** **B-04**.
**Blocks:** B-12 (the ask page doubles as the edit page).

---

## Problem

A question is permanent the moment it's posted — a typo in the title is forever, and a
question asked by mistake can't be withdrawn. Worse, a question held by moderation can
never be fixed, so its author has no path back to being visible.

## Proposed outcome

`PUT /api/questions/{id}` and `DELETE /api/questions/{id}` — author-only, with the edit
re-screened so a held question can be repaired and republished, and the delete cleaning
up everything that hung off it.

## Acceptance criteria

### Edit

- [ ] Author-only, via B-01's `load_owned` (404 missing, 403 not-yours).
- [ ] Same validation as create (title 10–200, body 30–30 000, ≤5 tags of 2–30, ≤10
      attachments).
- [ ] **Re-screen** the new text. The fresh verdict **replaces** the old status — that's
      what lets an author fix a held or rejected question and get it published.
- [ ] Re-bind attachments.
- [ ] There is **no question-edit notification event**. Don't invent one.
- [ ] Returns the refreshed `QuestionOut`.

### Delete

- [ ] Author-only. In **one transaction**:
  1. [ ] Clear `accepted_answer_id` **first** (the foreign key points at a row you're
         about to remove).
  2. [ ] Run the polymorphic cascades for the question **and all of its answers** —
         comments, votes, attachments.
  3. [ ] Delete the question. Answers cascade at the database level.
- [ ] After the commit, best-effort delete the attachment files from disk.
- [ ] Returns **204**.

## Out of scope

* Editing or deleting **answers** — B-07. Comments — B-09.
* An edit history or a "last edited by" trail. The `updated_at` column is the whole
  feature.
* Admin deletion of someone else's question. Moderators reject (D-07); they don't delete.
* The ask/edit **page** — B-12.

## The tests that grade this task

```bash
docker-compose exec backend pytest tests/lane_b/test_b05_edit_delete_question.py -v
```

Two tests, both substantial.

| Test | What it pins down | AC |
|---|---|---|
| `test_edit_updates_fields_author_only` | a non-author `PUT` → **403**; the author's `PUT` → **200** with `tags == ["edited"]` | ownership + update |
| `test_delete_cascades_answers_comments_votes` | a question with an answer, a comment **on the question**, a comment **on the answer**, a vote on the question and a vote on the answer → after `DELETE`, the `Answer`, `Comment` and `Vote` tables are each **globally empty** | the cascade |

That second test counts rows across the whole table, so anything left behind anywhere
fails it. Note what it's really checking: the comment on the *answer* and the vote on the
*answer* have no foreign key to the question at all. Nothing in the database will remove
them for you — that's why the AC says "the question **and all its answers**".

**Not graded here, but still required:** re-screening on edit (the moderation seam is
stubbed in a Lane B build, so no test can see it), the validation rules, clearing
`accepted_answer_id` before the delete, attachment cascade and file cleanup, and the
one-transaction requirement.

## Technical notes

**Constraints (requirements, not suggestions):**
* Order matters in the delete: clear the accepted pointer, cascade the children, then
  remove the parent. Any other order hits a constraint or orphans rows.
* Comments, votes and attachments hang off a `parent_type`/`parent_id` pair with **no SQL
  foreign key**. The database cannot cascade them. Your code must, in one transaction.
* Files come off disk **after** the commit. Delete them first and a rollback leaves rows
  pointing at nothing.

**Files you will probably touch:**
* `backend/app/routers/questions.py`, and B-01's `delete_comments_for` /
  `delete_votes_for`.

**Suggested approach:**
1. Edit first — it's create with a `load_owned` in front and no insert.
2. For delete, collect the answer ids **before** you delete anything; you need them for
   the cascades and they're unreachable afterwards.
3. Then: clear pointer → `delete_comments_for("question", [qid])` and
   `("answer", answer_ids)` → same for votes → `delete_attachments_for` (D-09's stub
   returns `[]` for now) → delete the question → commit → unlink the returned paths.

**Words you'll meet in this ticket:**
* **Cascade** — removing dependent rows when their parent goes. Here it's manual because
  the parent link is polymorphic.
* **Orphan row** — a child row whose parent is gone. Invisible, undeletable through the
  UI, and it makes counts wrong forever.
* **Re-screen** — running moderation again on edited text, so an edit can't smuggle
  content past the check that ran at creation.

## Verify it yourself

```bash
docker-compose exec backend pytest tests/lane_b/test_b05_edit_delete_question.py -v
```

By hand:
1. Edit someone else's question → 403. Edit your own → 200 with the new values.
2. Edit with a 5-character title → 400 with `fields.title`.
3. Build a question with 2 answers, comments on both levels, votes on both levels, and an
   accepted answer. Delete it → 204, and in `psql` **every** related row is gone:
   `questions`, `answers`, `comments`, `votes`.
4. Delete a question whose accepted answer is set → no foreign-key error.
5. Once D-02 has shipped: get a question held, edit it into something clean → it comes
   back `approved` and reappears in the feed.
