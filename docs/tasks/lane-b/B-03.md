# [B-03] Anyone can browse the questions people have asked

**Lane:** B — Q&A Core
**Task ID:** B-03
**Size:** ~1 day
**Depends on:** **B-01**.
**Blocks:** B-11 (the home page).

---

## Problem

Questions can be created and then only reached if you already know their id. There is no
list, so the app has no front door — and no way for a visitor to see whether the site has
anything on it.

## Proposed outcome

`GET /api/questions` — the paginated home feed, with three sorts, visible to logged-out
visitors, and never showing content that's been held for review.

## Acceptance criteria

- [ ] Query params: `sort ∈ newest | votes | unanswered` (default `newest`), `page`,
      `limit` (1–100).
- [ ] Works for **anonymous** viewers. Only visible questions are returned **and
      counted** (use B-01's `visible_filter`).
- [ ] `newest` → `created_at DESC`.
- [ ] `votes` → aggregated vote total DESC, then `created_at DESC`.
- [ ] `unanswered` → only questions with **no approved answer**, `created_at DESC`.
- [ ] Each item is a `QuestionListItem`: `{ id, title, excerpt, tags, author, vote_total,
      answer_count, view_count, has_accepted_answer, created_at }`.
- [ ] `answer_count` counts **approved** answers only.
- [ ] `excerpt` is the body with whitespace collapsed and truncated to 240 characters
      (`schemas/common.py` already exports `excerpt()`).
- [ ] Response `{ items, total, page, limit }`, where `total` respects the same filters
      as `items` — a held question must not inflate the count.

## Out of scope

* The home **page** — B-11.
* Search and filtering by tag/author/date — that's **D-11**, a separate endpoint with its
  own query language. Don't grow this one into it.
* Question detail — B-04.
* Infinite scroll, "hot" ranking, personalised feeds. Not in this project.

## The tests that grade this task

```bash
docker-compose exec backend pytest tests/lane_b/test_b03_question_feed.py -v
```

Three tests.

| Test | What it pins down | AC |
|---|---|---|
| `test_feed_newest_first_and_paginates` | 3 questions, `?sort=newest&page=1&limit=2` → `total == 3`, 2 items, and `items[0].created_at >= items[1].created_at` | pagination + newest |
| `test_unanswered_filter_excludes_answered` | a question with an **approved** answer is absent from `?sort=unanswered`; one with no answers is present | the unanswered filter |
| `test_held_questions_are_hidden_from_the_feed` | one `pending` question and nothing else → `total == 0` | visibility |

That third test asserts on **`total`**, not on `len(items)` — so filtering the page but
counting everything fails it. Apply the filter to both queries, or derive one from the
other.

**Not graded here, but still required:** the `votes` sort entirely, `answer_count`
counting approved answers only, the 240-character excerpt, `has_accepted_answer`, and the
`limit` bounds (1–100).

## Technical notes

**Constraints (requirements, not suggestions):**
* `total` respects the filters. This is the most commonly-shipped bug in list endpoints
  and it's the one the tests check hardest.
* Vote totals are aggregated on read (B-01) — there's no column to sort by, so the
  `votes` sort needs a join or a subquery against `votes`.
* Use `excerpt()` from `schemas/common.py`; four places truncate the same way.

**Files you will probably touch:**
* `backend/app/routers/questions.py`, `backend/app/schemas/question.py`.

**Suggested approach:**
1. Build one base query with `visible_filter` applied, then branch on `sort` for the
   ordering. Compute `total` from that same base query with `count()`.
2. `unanswered` is a `NOT EXISTS` against approved answers. `votes` is a `LEFT JOIN` onto
   a grouped subquery of `votes`, ordered by `COALESCE(sum, 0) DESC`.
3. Batch-load authors, vote totals and answer counts for the page's ids — three queries,
   then assemble in Python.

**Words you'll meet in this ticket:**
* **N+1 query** — running one query for the list and then one more per row. The classic
  reason a list endpoint is slow.
* **Aggregate** — a value computed across many rows (`SUM`, `COUNT`).
* **Subquery** — a query nested inside another, used here to attach vote totals.

## Verify it yourself

```bash
docker-compose exec backend pytest tests/lane_b/test_b03_question_feed.py -v
```

By hand:
1. `GET /api/questions` **logged out** → 200 with items.
2. Create 3 questions, vote one of them up twice → `?sort=votes` puts it first.
3. Answer one question → it disappears from `?sort=unanswered` but stays in `newest`.
4. Set a question to `pending` in `psql` → it vanishes from the feed **and** `total`
   drops by one.
5. `?limit=2` → 2 items and a correct `total`; page 2 returns the rest.
6. Post a question with a 3 000-character body → its `excerpt` in the feed is 240
   characters plus an ellipsis, on one line.
7. Turn on SQL echo (or watch the logs) with 20 questions in the feed → the query count
   stays flat, it doesn't scale with the page size.
