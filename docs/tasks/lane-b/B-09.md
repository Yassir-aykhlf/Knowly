# [B-09] A user can leave short comments on questions and on answers

**Lane:** B — Q&A Core
**Task ID:** B-09
**Size:** ~1 day
**Depends on:** **B-04**. Calls moderation (**D-02**) and notifications (**C-01**) — stubs.
**Blocks:** B-13's comment composers.

---

## Problem

There's no way to say "did you try restarting it?" without writing a full 30-character
answer. The `comments` table exists, B-04 already renders comment arrays at two levels,
and nothing can create a row in it.

## Proposed outcome

`POST /api/comments`, `PUT /api/comments/{id}`, `DELETE /api/comments/{id}` — one
polymorphic endpoint set that handles comments on questions and on answers alike.

## Acceptance criteria

### Create

- [ ] Body `{ parent_type: "question" | "answer", parent_id, body }`; `body` 1–1 000.
- [ ] The parent must exist **and be viewable** → **404 `not_found`** ("Parent content
      not found") otherwise.
- [ ] Comments **are moderated**, exactly like questions and answers. Being short is not
      a bypass.
- [ ] On approval, stage the **parent author's** `comment_created` notification plus any
      mentions. A held comment stages nothing.
- [ ] Return **201** `CommentOut` (which echoes `parent_type`).

### Edit

- [ ] Author-only. Re-screen; newly-added mentions fire.
- [ ] A post-grace edit of an **already-approved** comment notifies the **question**
      author with `content_edited`.
- [ ] If the parent chain has gone (the answer or question was deleted underneath),
      re-screen but stage **no** notifications — there's nowhere to point them.
- [ ] Return the refreshed `CommentOut`.

### Delete

- [ ] Author-only. If the comment was approved, stage `content_deleted` to the question
      author **before** deleting. Return **204**.

## Out of scope

* Threaded replies to comments. One level, on two parent types. That's it.
* Voting on comments. `votes` targets questions and answers only.
* Listing comments — they arrive inside B-04's question detail, never on their own.
* Attachments on comments.

## Technical notes

**Constraints (requirements, not suggestions):**
* `parent_type` must be validated against exactly `{"question", "answer"}` before you use
  it to pick a table. It arrives from the client.
* Note **who** gets notified, it differs by event: `comment_created` goes to the
  **parent's** author (the answer's author, if it's on an answer), while `content_edited`
  and `content_deleted` go to the **question's** author. B-01's `question_context` returns
  both ids in one call — use it.
* Comments go through moderation like everything else.

**Files you will probably touch:**
* `backend/app/routers/comments.py`, `backend/app/schemas/comment.py`.

**Suggested approach:**
1. A small `resolve_parent(parent_type, parent_id)` helper returning the model class and
   the loaded row, with the 404 inside it. All three endpoints use it.
2. Create: resolve → `can_view` → validate → insert → `screen_and_stage` → commit.
3. Edit and delete: `load_owned(db, Comment, ...)`, then the notification rules. Use
   `question_context` for the ids, and treat its `None` return as "stage nothing".

**Words you'll meet in this ticket:**
* **Polymorphic parent** — one child table pointing at two different parent tables via a
  type-plus-id pair. Flexible; the database can't enforce it, so you must.
* **Parent chain** — comment → answer → question. Walking it is how you find who to
  notify; it can be broken at any link.

## Verify it yourself

```bash
docker-compose exec backend pytest tests/lane_b/test_b09_comments.py -v
```

By hand:
1. Comment on a question and on an answer → both 201, and both appear in the right place
   in B-04's payload (top-level array vs nested under the answer).
2. Comment with `parent_type: "banana"` → 400, not a 500.
3. Comment with a 1 001-character body → 400.
4. Edit someone else's comment → 403.
5. Delete an **answer** that has a comment, then try to edit that comment → a clean
   error, not a stack trace.
6. Once C-01 has shipped: comment on someone's answer → **the answer's author** is
   notified. Delete that comment → **the question's author** is notified.
