# [C-03] The header bell shows unread notifications and opens a dropdown of the latest ones

**Lane:** C — Social & Signals
**Task ID:** C-03
**Size:** ~1–1.5 days
**Depends on:** **C-02** (all four endpoints).
**Blocks:** integration milestone 7 — this is the bell **everyone in the app sees**,
on every page, in every lane's screenshots.

---

## Problem

The app header currently shows a bell emoji that links to `/notifications` and does
nothing else. A user has no way of knowing something happened without clicking it,
so notifications are effectively invisible. Since C-02 shipped, the data to fix this
is one HTTP call away.

## Proposed outcome

`<NotificationBell>` in the header carries a live unread badge that refreshes on its
own, and clicking it opens a dropdown of the ten most recent notifications, each in
readable English, each clickable through to the thing that happened.

## Acceptance criteria

### The badge

- [ ] Shows the unread count from `GET /api/notifications/unread-count`.
- [ ] Refreshes **every 30 seconds** using the existing `usePolling` hook — which
      already pauses on a hidden tab and fires once when the tab is refocused. Use
      it; do not write your own `setInterval`.
- [ ] A failed poll (server down, network blip) keeps showing the **last known
      value** and quietly retries on the next tick. It must not flash to zero, and
      it must not pop a toast.
- [ ] Zero unread → no badge.

### The dropdown

- [ ] Clicking the bell opens a dropdown that fetches the latest **10**
      notifications — **each time it opens**, not once on mount.
- [ ] Each row shows: the wording from `describeNotification(n)`, the actor's
      avatar (`<Avatar>`), and a relative timestamp ("3 minutes ago").
- [ ] Clicking a row: marks it read (best-effort — if that call fails, navigate
      anyway), refreshes the unread count, and navigates to `n.link`.
- [ ] A "mark all read" action calls `PUT /api/notifications/read-all`, zeroes the
      badge, and visually clears the unread styling.
- [ ] Closes on an outside click **and** on `Escape`.
- [ ] Pressing `Escape` returns keyboard focus to the bell button. (A user who
      opened the dropdown with the keyboard must not be dumped at the top of the
      page.)

### The wording — `describeNotification(n)` in `lib/notifications.ts`

`lib/notifications.ts` already exists with a partial version. Finish it so **every**
event type in the vocabulary renders as a sentence. `{who}` is the actor's username,
or `"Someone"` when `actor` is `null`.

- [ ] `answer_created` → "{who} answered your question"
- [ ] `comment_created` → "{who} commented on your post"
- [ ] `vote_cast` → "{who} and N others voted on your {subject}" — where N comes
      from `actor_count`. **Never say up or down.** With `actor_count = 1`, drop the
      "and N others" clause and just say "{who} voted on your {subject}".
- [ ] `content_edited` → "{who} edited their {subject} on your question"
- [ ] `content_deleted` → "{who} deleted their {subject} on your question"
- [ ] `mentioned` → "{who} mentioned you in a {subject}"
- [ ] `friend_request` → "{who} sent you a friend request"
- [ ] `friend_accepted` → "{who} accepted your friend request"
- [ ] `friend_removed` → "{who} removed you as a friend"
- [ ] `moderation_pending` → "Your {subject} is being held for review"
- [ ] `moderation_approved` → "Your {subject} was approved and is now public"
- [ ] `moderation_rejected` → "Your {subject} was rejected by a moderator"
- [ ] The three `moderation_*` lines name **no actor** — a user never learns which
      moderator acted on their post.
- [ ] An `event_type` you don't recognise still renders something sane rather than
      crashing the header.

## Out of scope

- The full inbox page at `/notifications` — that's C-04, and it reuses this wording
  function, so keep `describeNotification` exported and free of bell-specific logic.
- Changing the API. If the bell needs a field the API doesn't send, that's a C-02
  change and a conversation, not a quiet edit.
- Live push / websockets. Polling every 30 s is the design.
- Desktop notifications or sound.

## Technical notes

**Constraints (requirements, not suggestions):**
- Use `usePolling` (`frontend/src/hooks/usePolling.ts`). It already handles the
  tab-visibility behaviour, which is genuinely fiddly to get right and which the
  ACs above require.
- Use the `api` wrapper in `lib/api.ts` for every request — never bare `fetch`. It
  sends the session cookie and parses the error envelope into a typed `ApiError`.
- `describeNotification` stays a pure function: notification in, string out. No
  hooks, no fetching. C-04 imports the same one.

**Files you will probably touch:**
- `frontend/src/components/NotificationBell.tsx` — replace the stub.
- `frontend/src/lib/notifications.ts` — finish `describeNotification`.
- `frontend/src/layouts/AppLayout.tsx` — already mounts `<NotificationBell />`; you
  probably don't need to touch it at all.
- `frontend/src/lib/format.ts` — already exports `relativeTime(iso)`. Use it; don't
  write another one.

**Suggested approach — a proposal, not a mandate:**
1. Finish `describeNotification` first. It's pure, testable in your head, and it's
   what C-04 needs from you.
2. Then the badge alone: fetch count on mount, `usePolling(fetchCount, 30_000)`.
   Keep the previous value in state and only overwrite on success.
3. Then the dropdown: `open` state, fetch on open, render rows.
4. Then the keyboard and outside-click behaviour last. `components/Modal.tsx`
   already solves focus-trap + Escape in this codebase — read it before inventing
   your own.

**Words you'll meet in this ticket:**
- **Polling** — asking the server "anything new?" on a timer, because the server has
  no way to push to us.
- **Visibility-aware** — pausing that timer when the browser tab is hidden, so a
  backgrounded tab isn't hammering the API all night. `usePolling` does this for you.
- **Best-effort call** — fire it, and if it fails, carry on with the user's actual
  intent anyway. Marking-read on click is best-effort; navigation is not.
- **Optimistic update** — change the UI immediately, assuming the server will agree.
  Here: zero the badge the moment "mark all read" is clicked.

## Verify it yourself

Run the stack, log in as user A, and have user B (private window) generate events.

1. B sends A a friend request (C-05) → within 30 s the badge shows **1** without a
   page reload.
2. Open the dropdown → the row reads "B sent you a friend request", with B's avatar
   and a relative time.
3. Click the row → it navigates to B's profile and the badge drops to 0.
4. Open the dropdown, press `Escape` → it closes, **and** the bell button is
   focused (press `Enter` — it should reopen without touching the mouse).
5. Open the dropdown, click somewhere else on the page → it closes.
6. Stop the backend (`docker-compose stop backend`), wait 60 s → the badge holds its
   last value and no error toast appears. Start it again → it recovers.
7. Switch to another browser tab for two minutes, come back → it refreshes once,
   immediately, on refocus.
8. Log in as a user with no notifications → no badge, dropdown shows an empty state.
